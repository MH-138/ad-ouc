认知障碍早期诊断临床数据采集系统 · 项目陈述

## 一、项目是什么

本项目是一款面向**阿尔茨海默病（AD）患者、家属及医生**的临床数据采集应用，以"智能对话访谈"为核心交互范式，服务于认知障碍早期筛查的基线评估。

**课程作业定位**：在 1 个月内交付一个**可演示的基础版本**，核心跑通"录入病人资料 + 填写量表 / 测试判断症状"主流程。项目交付物为**全栈正式系统** `ad-ouc-system/`（React + TypeScript + Express + LibSQL/Turso 云端数据库 + Gemini AI/OCR，为当前主交付物）。后续如需上线可平移到 uni-app（微信小程序 / 移动 App），见 `API接口设计.md` 与进度报告 P2 路线。

## 二、用户与角色

首页按三个通道分流，对应三类角色：

- **医师科研工作站（主试）**：发起评估、提问复杂量表、查看计分、生成综合报告、管理患者。
- **受试者自评（患者）**：自评简单量表、参与认知测试、查看泛化鼓励提示。
- **家属知情者（可选）**：补充患者日常功能与行为变化（FAQ / NPI / CDR）。

## 三、核心设计理念

- **去表格化**：把冰冷的"填表"变成有温度的"对话"。
- **适老化**：大按钮、大字体、高对比、防误触。
- **离线优先 + 云端可选**：断网可填写、重进可续聊（localStorage）；联网后由 `ad-ouc-system/` 后端（LibSQL/Turso 云端数据库）持久化患者与量表结果，也可从云端拉回。
- **智能辅助**：自动计分、红黄绿灯预警、各维度小计。

当前已落地能力（截至 2026-09-11，经 V3.0 三端解耦与 V3.2 深度重构两轮演进）：

- **三端彻底解耦**：受试者端、家属端、医生工作台三大通道独立，无前端角色切换；医生首页强制受试者队列守卫，未选人禁止访问量表与报告，杜绝跨端串流程、默认兜底。
- **云端数据库与多流草稿**：Turso LibSQL 4 张表（`patients` / `assessments` / `drafts` / `ai_consultations`）；草稿采用 `(patient_id, role, flow_id)` 联合主键，解决同角色多流程覆盖。
- **全套神经心理量表与计分**：MMSE-30、MoCA-B、AVLT-H、STT 连线、CDR（华盛顿大学分级算法）、FAQ、NPI、PSQI、HAMD-17、HAMA 等；未作答状态严格记空（`--` / `null`），绝不以 0 分或示例阳性分污染档案。
- **医疗多模态与 AI 审核闭环**：① 门诊病历 OCR 结构化提取并一键回填档案；② 神经心理绘图（双五边形 / 钟表描画 / 立方体）形态分析与智能打分；③ AI 临床研判（平滑动画 0%→100% + 动态流水号）经医生待审核队列 → 电子签名确认写回正式诊断。
- **身份识别与受试者管理**：规范 18 位身份证录入、自动反算实足周岁年龄与男/女；一键生成标准受试者；预设 4 位分层受试者（已签署 / 待审 / 空白）便于演示与对比。
- **随访医嘱闭环**：医生审核签署后，受试者端与家属端实时同步查看完整医嘱、签名与复查时间；未出具严格显示"暂未出具 (空)"。
- **工程质量**：TypeScript 严格类型检查 0 错误（`npm run lint`）、生产构建通过（`npm run build`），保持对历史代码零改动。

**验收状态**：截至 2026-09-11，`ad-ouc-system/01_当前实现差距与后续修改顺序.md` 中 13 项关键核查全部"已实现并通过端到端 / 联调验证"（三端入口、身份绑定、草稿隔离、云端档案、OCR、AI 推理、医生签字、随访闭环等）；最新提交已修复评审会议指出的问题（commit `37b6f00`）。

## 五、怎么运行 / 查看

### 全栈系统（主交付物）

完整的前后端一体系统位于 `ad-ouc-system/`（React + TypeScript 前端、Express + `tsx` + LibSQL/Turso 云端数据库 + Gemini AI/OCR 后端），运行与接口说明见 `ad-ouc-system/README.md`：

```bash
cd ad-ouc-system
npm install
npm run dev        # 前端 http://localhost:3000 + 后端 API
```

> 说明：未配置 `GEMINI_API_KEY` 时 AI / OCR 自动降级为规则引擎回退，核心量表与三端流程不受影响；离线本地运行须以内联环境变量（`TURSO_DATABASE_URL="file:./local-dev.db"`）启动。

## 八、当前限制

- **无真实登录鉴权**：提供演示级登录门禁与账号管理面板（纯前端、不联网、不加密），仅用于展示，不作真实鉴权；生产需接入鉴权 / HTTPS / 审计（见 `API接口设计.md` 第 11 节）。
