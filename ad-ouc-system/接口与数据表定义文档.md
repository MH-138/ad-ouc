# 认知障碍早期诊断临床数据采集系统 - 接口与数据表定义文档

> 文档版本：V1.0  
> 规范基准：代码库现有实现 (`server.ts` 与 `server/turso.ts`)，严格遵循 `P3_三端业务流程定稿.md`。

---

## 第一部分：数据库表结构定义 (Turso LibSQL / SQLite)

系统数据库包含 4 张核心业务数据表，负责受试者主档案、评定量表记录、跨端多流程草稿、AI 临床研判待审核与签字流。

### 1. `patients`（受试者主档案表）

存储受试者人口学基础信息、既往史、生物标志物及完整档案镜像。

| 字段名 | 数据类型 | 约束 | 字段说明与编程业务意义 |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | 受试者全局唯一主键，如 `sub-1725890123-456` |
| `research_no` | TEXT | - | 临床研究编号 / 门诊受试者识别号，如 `01-4921`、`SCD-2026-001` |
| `name` | TEXT | NOT NULL | 受试者真实姓名 |
| `gender` | TEXT | - | 性别编码：`1` 为男，`2` 为女，`0` 为未记录 |
| `birth_year` | INTEGER | - | 出生年份，如 `1958` |
| `age` | INTEGER | - | 实足年龄（岁） |
| `education_years` | INTEGER | - | 受教育年限（年），如小学6、初中9、高中12、本科16 |
| `occupation` | TEXT | - | 职业分类编码（1.干部 2.工人 3.农民 4.个体商业 5.其他） |
| `marital_status` | TEXT | - | 婚姻状况编码（1.已婚 2.未婚 3.离异 4.丧偶 5.再婚） |
| `living_arrangement` | TEXT | - | 居住状况编码（1.独居 2.与家人同住） |
| `height_cm` | REAL | - | 受试者身高（cm） |
| `weight_kg` | REAL | - | 受试者体重（kg） |
| `phone` | TEXT | - | 联系手机号码（11位） |
| `source` | TEXT | - | 病例来源渠道（1.社区筛查 2.医院门诊） |
| `created_by_role` | TEXT | - | 初始建档发起角色：`examiner`（医生）、`patient`（受试者）、`informant`（家属） |
| `history_json` | TEXT | - | 结构化既往病史 JSON（高血压、糖尿病、脑卒中、冠心病、高血脂、痴呆家族史等） |
| `biomarkers_json` | TEXT | - | 生物标志物检查 JSON（海马萎缩、Aβ-PET、Tau-PET、APOE基因型等） |
| `raw_data_json` | TEXT | - | 完整 `SubjectRecord` 实体序列化 JSON，保证全系统前端与分析引擎的数据完整兼容 |
| `created_at` | TEXT | - | 记录创建 ISO 8601 时间戳 |
| `updated_at` | TEXT | - | 记录最后修改 ISO 8601 时间戳 |

---

### 2. `assessments`（临床量表评定记录表）

存储各阶段各量表的评定完成状态、单项明细与分值。

| 字段名 | 数据类型 | 约束 | 字段说明与编程业务意义 |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | 量表评定记录唯一主键，如 `asm-1725890123` |
| `patient_id` | TEXT | NOT NULL | 外键关联 `patients.id` |
| `scale_code` | TEXT | NOT NULL | 量表标识码，如 `scdQ9`, `mmse`, `mocaB`, `cdr`, `avltH`, `faq`, `gds15`, `npi`, `psqi` 等 |
| `role` | TEXT | - | 评定执行角色：`examiner`（医生）、`patient`（受试者）、`informant`（知情者/家属） |
| `status` | TEXT | - | 评定状态：`completed`（已完成）、`in_progress`（进行中）、`skipped`（跳过） |
| `current_index` | INTEGER | - | 当前评定答题题号进度 |
| `answers_json` | TEXT | - | 单项作答明细键值对 JSON（题目ID: 作答分值/布尔值） |
| `score` | REAL | - | 量表计算总得分（未完成或跳过时必须为 NULL，绝不兜底为 0 分） |
| `global_cdr` | REAL | - | CDR 临床痴呆评定专属全局得分（0, 0.5, 1, 2, 3） |
| `level` | TEXT | - | 临床分级判定结论，如 `normal`, `borderline`, `abnormal` |
| `label` | TEXT | - | 临床评定标签文案 |
| `details_json` | TEXT | - | 扩展数据 JSON（如各认知域耗时、绘图 Base64、语义复述词条列表等） |
| `started_at` | TEXT | - | 评定启动时间戳 |
| `completed_at` | TEXT | - | 评定提交完成时间戳 |
| `created_at` | TEXT | - | 记录创建时间戳 |
| `updated_at` | TEXT | - | 记录更新时间戳 |

---

### 3. `drafts`（多端多业务流程草稿暂存表）

支持按受试者、端角色和业务流 ID 严格隔离草稿，杜绝同角色不同流程覆盖。

| 字段名 | 数据类型 | 约束 | 字段说明与编程业务意义 |
|---|---|---|---|
| `patient_id` | TEXT | NOT NULL | 外键关联 `patients.id` |
| `role` | TEXT | NOT NULL | 端角色：`patient`、`informant`、`examiner` |
| `flow_id` | TEXT | NOT NULL | 业务流/量表流程唯一标识（如 `scd_self`、`faq_cdr`、`default`） |
| `flow_type` | TEXT | - | 流程分类类型编码 |
| `current_index` | INTEGER | - | 暂存时的题号进度序号 |
| `answers_json` | TEXT | - | 暂存的部分作答键值对 JSON |
| `draft_json` | TEXT | - | 完整草稿上下文对象序列化 JSON |
| `status` | TEXT | - | 草稿状态，如 `drafting` |
| `client_updated_at` | TEXT | - | 客户端本地触发保存的时间戳 |
| **联合主键** | - | **PRIMARY KEY (patient_id, role, flow_id)** | 联合主键，确保同一受试者的不同角色、不同业务流程草稿互不覆盖 |

---

### 4. `ai_consultations`（AI 临床智能研判与医生审核签字表）

实现“AI 推理生成 -> 存入待审核队列 -> 医生审查修改 -> 电子签名确认 -> 写入正式诊断”的医疗闭环。

| 字段名 | 数据类型 | 约束 | 字段说明与编程业务意义 |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | 研判记录唯一标识，如 `ai-cons-1725890123-abc` |
| `patient_id` | TEXT | NOT NULL | 外键关联 `patients.id` |
| `patient_name` | TEXT | - | 受试者姓名（冗余字段便于快速检索） |
| `status` | TEXT | NOT NULL | 审核状态：`pending_review`（待医生审核签字）、`approved`（医生已签字确认生效） |
| `suggested_diagnosis` | TEXT | - | AI 推荐临床分型建议（如 `SCD (主观认知下降)`、`aMCI`、`NC`） |
| `confidence` | REAL | - | AI 诊断推理置信度（0.00 ~ 1.00） |
| `ai_summary_json` | TEXT | - | 结构化推理报告 JSON（综合印象、六大认知域评定、核心异常、建议） |
| `doctor_signature` | TEXT | - | 临床主治医生电子签字签名（如 `韩璎`） |
| `doctor_notes` | TEXT | - | 医生最终签署的正式临床诊断意见与随访医嘱 |
| `created_at` | TEXT | - | AI 研判生成入库时间戳 |
| `reviewed_at` | TEXT | - | 医生完成签字审核时间戳 |

## 第二部分：HTTP API 接口定义与路径规范 (`server.ts`)

系统服务统一运行于 HTTP 端口 `3000`。所有业务请求及响应均采用 `application/json` 格式。

### 1. 系统基础与数据库状态

#### 1.1 服务健康检查
- **请求方法**：`GET`
- **请求路径**：`/api/health`
- **功能说明**：检测后端 Web 服务存活状态。
- **响应参数**：
  ```json
  {
    "status": "ok",
    "timestamp": "2026-09-10T06:30:00.000Z"
  }
  ```

#### 1.2 Turso 数据库连接状态与延迟检测
- **请求方法**：`GET`
- **请求路径**：`/api/v1/db/status`
- **功能说明**：返回 Turso LibSQL 云端连接可用性、往返网络延迟毫秒数、受试者与测评记录统计总量。
- **响应参数**：
  ```json
  {
    "success": true,
    "data": {
      "connected": true,
      "url": "libsql://ad-ouc-mh-138.aws-ap-northeast-1.turso.io",
      "latencyMs": 120,
      "patientCount": 5,
      "assessmentCount": 18,
      "timestamp": "2026-09-10T06:30:00.000Z"
    }
  }
  ```

### 2. 受试者档案管理接口 (Patients)

#### 2.1 获取受试者队列列表
- **请求方法**：`GET`
- **请求路径**：`/api/v1/patients`
- **查询参数**：
  - `name`（可选，字符串）：按受试者姓名模糊检索
  - `researchNo`（可选，字符串）：按科研编号检索
- **响应参数**：`{ "success": true, "data": SubjectRecord[] }`

#### 2.2 获取指定受试者详情
- **请求方法**：`GET`
- **请求路径**：`/api/v1/patients/:id`
- **路径参数**：`id`（受试者全局唯一主键 ID）
- **响应参数**：`{ "success": true, "data": SubjectRecord }`（未找到时返回 404）

#### 2.3 新建受试者档案
- **请求方法**：`POST`
- **请求路径**：`/api/v1/patients`
- **请求体（JSON）**：符合 `SubjectRecord` 结构的档案对象（必填 `name`、`gender`、`age` 等）
- **响应参数**：`{ "success": true, "data": SubjectRecord }`（状态码 `201 Created`）

#### 2.4 更新受试者档案
- **请求方法**：`PATCH`
- **请求路径**：`/api/v1/patients/:id`
- **路径参数**：`id`（受试者全局唯一主键 ID）
- **请求体（JSON）**：待增量更新的档案字段键值对
- **响应参数**：`{ "success": true, "data": SubjectRecord }`

#### 2.5 删除受试者档案
- **请求方法**：`DELETE`
- **请求路径**：`/api/v1/patients/:id`
- **路径参数**：`id`（受试者全局唯一主键 ID）
- **响应参数**：`{ "success": true }`

#### 2.6 批量初始化受试者预设队列 (Seed)
- **请求方法**：`POST`
- **请求路径**：`/api/v1/seed-cohort`
- **请求体（JSON）**：`{ "cohort": SubjectRecord[] }`
- **功能说明**：用于空库时写入典型 SCD、早期 MCI 与健康对照三组临床标准对照样本。
- **响应参数**：`{ "success": true, "count": number }`

### 3. 量表评定接口 (Assessments)

#### 3.1 保存单项量表评定结果
- **请求方法**：`POST`
- **请求路径**：`/api/v1/patients/:patientId/assessments`
- **路径参数**：`patientId`（受试者 ID）
- **请求体（JSON）**：
  ```json
  {
    "scaleCode": "mmse",
    "role": "examiner",
    "status": "completed",
    "score": 28,
    "answers": { "2.1": 1, "2.2": 1 },
    "details": {}
  }
  ```
- **响应参数**：`{ "success": true, "data": assessmentRecord }`

---

### 4. 角色与多流程草稿接口 (Drafts)

#### 4.1 读取角色流程草稿
- **请求方法**：`GET`
- **请求路径**：`/api/v1/patients/:patientId/drafts/:role/:flowId?`
- **路径参数**：
  - `patientId`（受试者 ID）
  - `role`（角色：`patient`、`informant`、`examiner`）
  - `flowId`（可选，业务流标识符，缺省为 `default`）
- **响应参数**：`{ "success": true, "data": draftRecord | null }`

#### 4.2 保存/覆盖角色流程草稿
- **请求方法**：`PUT`
- **请求路径**：`/api/v1/patients/:patientId/drafts/:role/:flowId?`
- **请求体（JSON）**：
  ```json
  {
    "flowId": "faq_cdr",
    "currentIndex": 4,
    "answers": { "1": 1, "2": 0 },
    "draftJson": { "informantRelation": "配偶", "items": { "1": 1 } },
    "clientUpdatedAt": "2026-09-10T14:00:00.000Z"
  }
  ```
- **响应参数**：`{ "success": true }`

### 5. AI 智能辅助分析与推理接口 (AI Services)

#### 5.1 综合认知域分析与诊断建议
- **请求方法**：`POST`
- **请求路径**：`/api/ai/analyze-assessment`
- **功能说明**：汇总多模态量表数据（MMSE, MoCA, AVLT, STT, CDR 等）与生物标志物，调用 Gemini 生成结构化认知域评估与鉴别诊断报告；无 API Key 时自动降级为规则引擎。
- **请求体（JSON）**：
  ```json
  {
    "patientData": { ... },
    "assessmentSummary": { ... }
  }
  ```
- **响应参数**：
  ```json
  {
    "success": true,
    "isAiGenerated": true,
    "analysis": {
      "overallImpression": "...",
      "domainAssessment": { ... },
      "suggestedDiagnosis": "SCD (主观认知下降)",
      "keyAbnormalities": [ ... ],
      "recommendations": [ ... ]
    }
  }
  ```

#### 5.2 临床综合研判三段式推理
- **请求方法**：`POST`
- **请求路径**：`/api/ai/clinical-reasoning`
- **功能说明**：生成规范临床研判文本（结论、依据、随访处理建议），标注需主治医师签字后生效。
- **请求体（JSON）**：`{ "record": SubjectRecord, "userPrompt": string }`
- **响应参数**：
  ```json
  {
    "success": true,
    "reasoningText": "...",
    "requiresDoctorSignature": true
  }
  ```

#### 5.3 神经心理绘图智能分析打分
- **请求方法**：`POST`
- **请求路径**：`/api/ai/analyze-drawing`
- **功能说明**：接收前端 Canvas 临摹图片 Base64，自动评定双五边形交叉（MMSE）、CDT 钟表描画或三维立方体（MoCA）。
- **请求体（JSON）**：
  ```json
  {
    "drawingBase64": "data:image/png;base64,...",
    "referenceType": "dualPentagons",
    "title": "MMSE双五边形测验"
  }
  ```
- **响应参数**：
  ```json
  {
    "success": true,
    "isAiGenerated": true,
    "result": {
      "score": 1,
      "maxScore": 1,
      "status": "normal",
      "clinicalComment": "双五边形闭合完整，交叉形成规则四边形交集，得 1/1 分。"
    }
  }
  ```

### 6. AI 研判待办与医生签字接口 (AI Consultations Workflow)

#### 6.1 获取待签字审核的研判列表
- **请求方法**：`GET`
- **请求路径**：`/api/v1/ai-consultations/pending`
- **功能说明**：查询当前处于 `pending_review` 状态的 AI 研判待办列表。
- **响应参数**：
  ```json
  {
    "success": true,
    "count": 1,
    "items": [
      {
        "id": "ai-cons-1725890123-abc",
        "patient_id": "sub-001",
        "patient_name": "张建华",
        "status": "pending_review",
        "suggested_diagnosis": "SCD",
        "confidence": 0.88,
        "ai_summary_json": "{ ... }",
        "created_at": "2026-09-10T14:10:00.000Z"
      }
    ]
  }
  ```

#### 6.2 提交 AI 研判结果进入待审核队列
- **请求方法**：`POST`
- **请求路径**：`/api/v1/ai-consultations/submit`
- **请求体（JSON）**：
  ```json
  {
    "patientId": "sub-001",
    "patientName": "张建华",
    "suggestedDiagnosis": "SCD (主观认知下降)",
    "confidence": 0.88,
    "aiSummary": { ... }
  }
  ```
- **响应参数**：`{ "success": true, "id": "ai-cons-..." }`

#### 6.3 医生签字确认并写入最终诊断
- **请求方法**：`POST`
- **请求路径**：`/api/v1/ai-consultations/:id/approve`
- **路径参数**：`id`（研判记录 ID）
- **请求体（JSON）**：
  ```json
  {
    "doctorSignature": "韩璎 教授",
    "doctorNotes": "同意分型结论，建议6个月后神经心理量表复查。",
    "confirmedCategory": 2
  }
  ```
- **功能说明**：将审核状态置为 `approved`，同时自动将医生签名与临床诊断写回 `patients` 表中对应受试者的 `raw_data_json.diagnosis` 与 `raw_data_json.followUp` 字段。
- **响应参数**：`{ "success": true, "patientId": "sub-001" }`

### 7. 医疗文档 OCR 与智能信息提取接口 (Document Extraction)

#### 7.1 病历/检验单图像与文本智能结构化提取
- **请求方法**：`POST`
- **请求路径**：`/api/ai/parse-medical-record`
- **请求体（JSON）**：
  ```json
  {
    "fileBase64": "data:image/jpeg;base64,...",
    "mimeType": "image/jpeg",
    "rawText": "患者姓名：孙桂兰，性别：女，年龄：69岁..."
  }
  ```
- **响应参数**：
  ```json
  {
    "success": true,
    "isAiGenerated": true,
    "parsedData": {
      "name": "孙桂兰",
      "gender": 2,
      "age": 69,
      "educationYears": 16,
      "chiefComplaint": "自觉近1年记忆力减退...",
      "history": {
        "hypertension": true,
        "diabetes": false,
        "cerebrovascular": false
      },
      "confidenceScore": 0.95
    }
  }
  ```

#### 7.2 解析内置示例病历
- **请求方法**：`POST`
- **请求路径**：`/api/v1/ocr/parse-record`
- **请求体（JSON）**：`{ "sampleKey": "case_sun", "fileName": "宣武医院门诊病历_孙桂兰.pdf" }`
- **响应参数**：`{ "success": true, "data": parsedRecord }`

#### 7.3 获取系统内置示例病历列表
- **请求方法**：`GET`
- **请求路径**：`/api/v1/ocr/samples`
- **响应参数**：`{ "success": true, "samples": [ { "key": "...", "title": "...", "preview": "..." } ] }`
