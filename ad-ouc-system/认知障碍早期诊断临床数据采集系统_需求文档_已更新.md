# 认知障碍早期诊断临床数据采集系统 —— 需求文档

---

## 1. 项目概述

### 1.1 项目目标

> **让使用者（患者、家属、医生）能够便捷地录入病人资料，并通过填写量表或认知测试，自动判断病人的症状情况。**

一款以「智能对话访谈」为核心交互范式的小程序 / 移动端软件，服务于认知障碍早期筛查的基线评估与随访演示。

### 1.2 产品定位

- 核心交互：模拟微信聊天的气泡消息流，把「填表」变成「对话」
- 适用终端：科室平板 / 手机

### 1.3 交付形态

| 形态                   | 说明                | 课程建议               |
| ---------------------- | ------------------- | ---------------------- |
| **微信小程序（推荐）** | 聊天式 UI + 云开发  | 演示最直观；可用测试号 |
| **纯前端 + 本地存储**  | 浏览器 / 模拟器演示 | 最简单，适合作业提交   |

### 1.4 设计理念

- **去表格化**：把冰冷的「填表」转化为有温度的「对话」
- **适老化**：大按钮、大字体、语音朗读、防误触
- **离线优先**：病房 Wi-Fi 不稳定，支持断网填写、自动同步
- **智能辅助**：自动计分、异常预警、病历文档 AI 解析

## 2. 用户角色

| 角色                      | 职责                           | 说明             |
| ------------------------- | ------------------------------ | ---------------- |
| **患者（受访者）**        | 自评简单量表、回答问题         | 大按钮、语音朗读 |
| **主试（医生 / 研究者）** | 发起评估、录入观察项、查看计分 | 角色切换即可     |
| **家属（知情者，可选）**  | 补充患者日常情况               | 人称自动切换     |

> 课程演示以「主试 + 患者」双视角为主；不做复杂权限管理、多中心协作等系统。

---

## 3. 核心交互：聊天式对话引擎

| 交互元素            | 说明                                                       |
| ------------------- | ---------------------------------------------------------- |
| **左侧气泡**        | AI / 主试的提问或引导语，含 TTS 语音朗读小喇叭             |
| **右侧气泡**        | 患者的回答记录（自动生成）                                 |
| **快捷回复卡片**    | 紧贴气泡下方的大按钮组（2~4 个），如「是的 / 不是 / 偶尔」 |
| **情感表情尺**      | 5 级表情（😊🙂😐🙁😭），用于自评工具（如 GDS）             |
| **数字滚轮**        | 年龄、年限、血压等数值输入，调用原生 Picker                |
| **轮次进度卡片**    | AVLT 专用，显示第 N 轮，点击词条变绿计分                   |
| **拍照 / 上传卡片** | 病历拍照、签名拍照、MoCA 画图拍照上传                      |

**对话流程控制**

- **决策树驱动**：所有对话节点由 JSON 配置文件定义，包含话术、选项按钮、跳转逻辑
- **自动跳题**：选「无高血压」则自动跳过后续降压药相关问题
- **断点续聊**：每一条聊天气泡自动缓存，退出重进原地恢复
- **角色无感切换**：聊到「知情者问卷」时自动询问家属，切换后问题人称自动变化

## 4. 功能需求

### 4.1 患者建档（聊天式）

进入小程序后第一段对话自动引导建档。

**核心字段**：姓名、性别、年龄（出生日期自动计算）、身高、体重、受教育年限、职业、婚姻状况、居住情况、联系方式、研究编号（演示自动生成）。

- 支持手动录入；病历拍照识别作为可选增强（见 4.6）
- 年龄由出生日期自动计算

### 4.2 量表评估（对话式，10 个核心模块）

**话题拆解（柔和化拆分）**：暖场破冰 → 身体小毛病 → 记性咋样 → 心情与睡觉 → 互动小游戏 → 家人怎么看。

| #   | 量表                      | 简称   | 完成方式      | 计分（课程用固定阈值）                                         |
| --- | ------------------------- | ------ | ------------- | -------------------------------------------------------------- |
| 1   | 主观认知下降自测表        | SCD-Q9 | 患者自评      | 是=1/否=0；经常=1/偶尔=0.5，求和                               |
| 2   | 汉密尔顿抑郁量表（17 项） | HAMD   | 主试逐题      | 0–4 / 0–2 录入求和；<7 正常 / ≥7 可能 / ≥17 肯定 / ≥24 严重    |
| 3   | 汉密尔顿焦虑量表          | HAMA   | 主试逐题      | 0–4 录入求和；<7 无 / ≥7 可能 / ≥14 肯定 / ≥21 明显 / ≥29 严重 |
| 4   | 简明精神状态检查          | MMSE   | 主试提问      | 30 项求和；教育节点预警（文盲 17 / 中学 20 / 大学 24）         |
| 5   | 蒙特利尔认知评估基础量表  | MoCA-B | 主试提问      | 求和；节点（文盲小学 19 / 中学 22 / 大学 24）                  |
| 6   | 听觉词汇学习测验          | AVLT   | 主试口述      | N1–N5 即时 + 延迟回忆 + 再认，逐轮计分                         |
| 7   | 词语流畅性测试            | VFT    | 主试计时      | 60 秒计正确词数                                                |
| 8   | 功能活动问卷              | FAQ    | 知情者        | 10 项四级求和；≥9 提示                                         |
| 9   | 神经精神量表              | NPI    | 知情者        | 频率 × 严重度 + 痛苦度                                         |
| 10  | 临床痴呆评定量表          | CDR    | 主试 + 知情者 | 6 域 → Global CDR + CDR-SB                                     |

**特殊测试的移动端交互**

- **AVLT**：词条默认遮罩防泄题，主试点「记起一个」才弹九宫格；延迟回忆按标准流程间隔（演示用定时器提示）；侵入词/重复词可记录
- **VFT**：倒计时数字大屏，最后 10 秒变红闪烁；主试手动输入患者说出的词
- **BNT / MoCA 图片**：用示意图或公开样图展示，双指捏合缩放，下方「正确 / 提示 / 错误」大按钮
- **STT 连线 / MES 手指动作**：课程演示可省略触屏绘图与视频，相关条目用文字录入或留接口

### 4.3 自动计分与预警

每完成一个量表，系统自动计算得分并以「聊天消息」形式告知结果。

- 分数数字 + **红 / 黄 / 绿三色状态灯**
  - 🟢 绿色 = 正常
  - 🟡 黄色 = 临界 / 需关注
  - 🔴 红色 = 异常 / 需干预
- 同时显示判定结论（如「您目前的抑郁评分处于正常范围，继续保持！」）
- **患者侧**：仅显示泛化鼓励 + 「建议由医生进一步评估」；详细分数与灯色在主试视图与导出报告中出现

### 4.4 随访（简化）

- 患者详情页顶部「时间轴」标签页：基线期 | 第 1 年 | 第 2 年 …
- 切换年份加载对应访视数据；同一量表不同年份以**趋势箭头**展示（如「MMSE：28 → 26 → 24 ↓」）
- 课程演示可只做「基线 + 1 次随访」

### 4.5 数据导出

- 首页「导出数据」大按钮，选择导出范围（单个患者 / 全部患者 / 某次随访）
- 导出格式：Excel（.xlsx），含患者基本信息 + 各量表总分 / 分级 + 诊断建议
- 匿名化选项（勾选后脱敏姓名、身份证号）

### 4.6 病历智能识别（可选增强）

- 拍照 / 上传 → OCR + 大模型提取姓名 / 年龄 / 诊断 / 用药 → 人工复核确认后填入档案
- 课程演示可先做简单 OCR 或预留接口；识别结果**需人工确认**，不自动覆盖已有数据

## 5. 非功能需求

| 类别         | 具体要求                                                      |
| ------------ | ------------------------------------------------------------- |
| **适老化**   | 字体 ≥ 17pt；点击热区 ≥ 44pt；支持语音朗读 TTS；色彩对比度高  |
| **离线支持** | 每步操作自动缓存本地；断网显示「离线模式」；联网后自动同步    |
| **响应速度** | 页面切换 ≤ 1 秒；自动计分即时（<100ms）                       |
| **设备兼容** | 支持 iOS 11+ / Android 8+；适配 7 寸以上平板及主流手机        |
| **安全性**   | 本地数据加密存储；涉及 API 上传时获用户授权；不上传公开训练集 |

## 6. 技术选型建议

| 层级                 | 推荐选型                    | 理由                                               |
| -------------------- | --------------------------- | -------------------------------------------------- |
| **前端**             | uni-app（Vue3）             | 一套代码编译微信小程序 + Android APK               |
| **UI 组件**          | uView / Vant Weapp          | 大按钮、滚轮、弹窗开箱即用                         |
| **状态管理**         | Pinia（持久化插件）         | 天然支持本地缓存，轻松实现离线草稿                 |
| **后端（可选）**     | 微信云开发 或 纯本地 + 导出 | 云开发省部署、自动同步；纯本地最简单，适合作业提交 |
| **OCR 识别（可选）** | 腾讯云 OCR + DeepSeek       | 按量计费，开发量小                                 |

---

## 7. 开发排期（4 周 MVP）

| 周次        | 核心任务                                                 | 交付物                         |
| ----------- | -------------------------------------------------------- | ------------------------------ |
| **第 1 周** | 搭建环境；患者建档模块；聊天引擎核心框架                 | 可运行的建档 + 聊天界面原型    |
| **第 2 周** | 10 个量表决策树 JSON；对话渲染；自动计分 + 红黄绿灯      | 全部 10 个量表可走通（含计分） |
| **第 3 周** | VFT 计时 / AVLT 轮次；拍照上传；数据导出 Excel；离线缓存 | 导出与离线可用                 |
| **第 4 周** | 联调测试；1~2 例示例数据试录入；验收演示                 | 可用于演示的版本               |

---

## 8. 验收标准

1. 小程序 / 软件可运行，建档 + 10 个量表完整走通
2. 自动计分与红黄绿灯预警正确（对照手工算分样例）
3. 一键导出 Excel 成功，含患者信息与量表结果
4. 断网填写 → 退出 → 续填 → 联网同步演练通过
5. 内置 1~2 例示例患者用于演示与测试

---

## 10. 交付物总结

4 周后，您将获得：

1. 一个可运行的小程序 / 软件，安装至平板或手机（或浏览器演示）
2. 10 个核心量表的完整对话式评估流程，含自动计分与红黄绿灯预警
3. 聊天式患者建档，含基础信息录入（病历识别为可选增强）
4. 离线草稿箱，断网可用，联网自动同步
5. 一键导出 Excel，含患者全部评估数据
6. 完整的对话剧本 JSON 配置文件，后续新增量表仅需扩展此文件
