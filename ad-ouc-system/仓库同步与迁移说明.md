# 仓库代码同步与迁移指南

> **用途说明**：当您在主开发目录 `code/` 中完成代码修改、页面润色或文档更新后，请参照本指南将更新安全、无遗漏地同步到 Git 仓库 `ad-ouc/ad-ouc-system/` 中，以便进行 Git 提交与远程推送。

---

## 一、必须迁移（直接复制）的内容清单

在 `code/` 中修改后，**必须同步覆盖**到 `ad-ouc/ad-ouc-system/` 的内容：

### 1. 核心源代码与服务端
- `src/`（整目录递归覆盖：包含所有前端页面、量表、公共组件、类型定义与工具函数）
- `server/`（整目录递归覆盖：包含 Turso LibSQL 客户端连接、OCR 文档解析服务）
- `server.ts`（后端 Express 入口服务与 API 路由定义）

### 2. 工程配置文件
- `package.json`（依赖配置与 scripts 脚本）
- `package-lock.json`（依赖锁定版本）
- `tsconfig.json`（TypeScript 编译规则）
- `vite.config.ts`（Vite 现代化打包构建配置）
- `index.html`（SPA 页面主入口模板）
- `.env.example`（环境变量配置示例模版）
- `.gitignore`（Git 忽略规则配置文件）

### 3. 正式业务与技术文档
- `README.md`（系统工程主说明文档）
- `P3_三端业务流程定稿.md`（当前唯一核心业务流程基准）
- `接口与数据表定义文档.md`（4 大数据库表与 16 个 API 接口规范）
- `CHANGELOG_AND_IMPROVEMENTS.md`（详细变更与工作留痕日志）
- `API_AND_DATA_SPEC.md`（接口与临床数据技术契约）
- `00_文档归属与阅读顺序.md`（文档分类与阅读次序）
- `01_当前实现差距与后续修改顺序.md`（差距核对与验收状态）
- `P2_接口设计与OCR结构化解析交付文档.md`（OCR 技术说明）
- `P1_功能迁移与云端数据库接入说明.md`（历史记录）
- `P2_工作交付与版本迭代说明.md`（历史记录）
- `认知障碍早期诊断临床数据采集系统_需求文档_已更新.md`（需求参考）

## 二、严禁迁移（绝对不要复制）的内容清单

以下内容属于本地运行产物、敏感凭据或临时归档，**严禁复制**到 `ad-ouc/ad-ouc-system/`：

| 目录 / 文件 | 不迁移原因 |
|---|---|
| `node_modules/` | 体积巨大（数百兆），应由目标目录通过 `npm install` 自动还原安装。 |
| `dist/` | 生产构建编译产物，不应由源码仓库追踪。 |
| `.env` | 包含本地真实的私有 API Key 或数据库 Token，上传会导致凭据外泄。 |
| `*.log`（如 `dev-server.log` 等） | 本地服务运行日志与调试日志。 |
| `ad-ouc-ref/` 与 `ad-ouc-unpacked/` | 历史版本原型解压归档包，Git 根目录已有 `ad-ouc-prototype/`，切勿重复复制。 |
| `*.zip` 压缩包 | 二进制归档文件不应纳入日常代码提交。 |
| 内部草稿 / 带个人称谓的临时文档 | 如包含明文 Token 的背景备忘文档、内部交接清单等，杜绝外传。 |

## 三、一键自动化同步迁移命令 (PowerShell)

在项目根目录（`D:\project\ouc-ad\`）打开 PowerShell 终端，直接复制并运行以下命令，即可全自动完成文件同步覆盖：

```powershell
# 1. 定义源目录与目标仓库目录
$srcDir = "D:\project\ouc-ad\code"
$destDir = "D:\project\ouc-ad\ad-ouc\ad-ouc-system"

# 2. 同步核心源码与服务端模块
Copy-Item -Recurse -Force "$srcDir\src" "$destDir\src"
Copy-Item -Recurse -Force "$srcDir\server" "$destDir\server"
Copy-Item -Force "$srcDir\server.ts" "$destDir\"

# 3. 同步项目配置文件
Copy-Item -Force "$srcDir\package.json" "$destDir\"
Copy-Item -Force "$srcDir\package-lock.json" "$destDir\"
Copy-Item -Force "$srcDir\tsconfig.json" "$destDir\"
Copy-Item -Force "$srcDir\vite.config.ts" "$destDir\"
Copy-Item -Force "$srcDir\index.html" "$destDir\"
Copy-Item -Force "$srcDir\.env.example" "$destDir\"
Copy-Item -Force "$srcDir\.gitignore" "$destDir\"

# 4. 同步正规业务技术文档 (排除带敏感称谓或私密 Token 的文档)
$validDocs = @(
  "README.md",
  "P3_三端业务流程定稿.md",
  "接口与数据表定义文档.md",
  "CHANGELOG_AND_IMPROVEMENTS.md",
  "API_AND_DATA_SPEC.md",
  "00_文档归属与阅读顺序.md",
  "01_当前实现差距与后续修改顺序.md",
  "P2_接口设计与OCR结构化解析交付文档.md",
  "P1_功能迁移与云端数据库接入说明.md",
  "P2_工作交付与版本迭代说明.md",
  "认知障碍早期诊断临床数据采集系统_需求文档_已更新.md"
)

foreach ($doc in $validDocs) {
  if (Test-Path "$srcDir\$doc") {
    Copy-Item -Force "$srcDir\$doc" "$destDir\"
  }
}

Write-Host ">>> 同步完成！接下来进入 ad-ouc-system 运行构建校验..." -ForegroundColor Green
Set-Location "$destDir"
npm run lint
npm run build
```

## 四、同步后的标准提交步骤 (Git Commit)

完成上述同步并确认 `npm run lint` 及 `npm run build` 均无报错后，在 `D:\project\ouc-ad\ad-ouc\` 目录执行 Git 提交：

```bash
cd D:\project\ouc-ad\ad-ouc

# 1. 查看待提交文件变动（确认无 node_modules 或 .env 泄露）
git status

# 2. 暂存变动并提交
git add .
git commit -m "feat: V3.0 三端业务解耦与系统交付更新"

# 3. 推送到远程 GitHub 仓库
git push origin main
```
